# Cats

Автономный Docker Compose стек сайта с доступом по IP через HTTP. Исходники, Dockerfile
приложения, внешний Nginx и его конфиги находятся в этом репозитории.
Клонировать nginx-config для сборки и деплоя больше не требуется.

## Структура

- `app/` — Vue/Vite приложение и его внутренний Nginx на порту 3000.
- `nginx/` — отдельный образ публичного HTTP-прокси, настройки безопасности,
  лимиты запросов и виртуальный хост cats.
- `compose.yaml` — два сервиса: cats-app и nginx-core, отдельная сеть проекта cats.
- `.github/workflows/deploy.yml` — раздельные джобы build-app, build-nginx и deploy.

Конфиги внешнего Nginx включены в образ, а не подключены из checkout через bind
mount. Очистка рабочего каталога runner не затрагивает работающий сайт.

## Подготовка сервера

Нужны Docker Engine, Docker Compose plugin 2.20+ и Linux ARM64 runner на сервере.
Пользователь службы runner должен иметь доступ к Docker без интерактивного sudo.
Все три джобы используют локальные образы и должны выполняться на одном Pi.
Если появятся другие ARM64 runner, назначьте этому Pi уникальную метку и добавьте
её в runs-on во всех трёх джобах.

Домен, сертификаты и Certbot не требуются. Nginx принимает запросы по IP на
порту 80 и передаёт их cats-app:3000 по внутренней сети Docker.

## Первый запуск

Порт 80 должен быть свободен. Прежний общий nginx-core из nginx-config
занимает тот же порт: два таких стека не могут одновременно слушать один IP
на порту 80. Сначала перенесите остальные сайты или освободите этот порт.
В исходном nginx-config удалены только сервис cats-app, зависимость от него
и его виртуальный хост; home и qr-scanner остаются в старом стеке.
Работающие контейнеры автоматически не останавливались.

Из корня cats:

```bash
docker compose build cats-app
docker compose build nginx-core
docker compose run --rm --no-deps nginx-core nginx -t
docker compose up -d --no-build --wait --wait-timeout 90
docker compose ps
```

Откройте `http://<IP-сервера>/`. Для доступа из интернета firewall/роутер должен
пропускать TCP-порт 80 на Pi. Для доступа из домашней сети используйте LAN IP Pi.

## GitHub Actions

После push в master с изменениями приложения, nginx или Compose:

1. build-app собирает только приложение.
2. build-nginx независимо собирает только Nginx с конфигами.
3. deploy ждёт обе сборки, проверяет образы и конфигурацию Nginx,
   затем обновляет стек и ждёт healthcheck.

Ручной запуск: Actions → Build and deploy cats → Run workflow → master.
Образы получают общий тег commit-run_id и остаются на Pi. Тег сохраняется при
повторном запуске упавших джоб, чтобы deploy видел уже собранные образы.
Деплой не скачивает исходники второго репозитория и не использует registry/SSH.
Зависимости frontend устанавливаются строго по app/bun.lock.

Сбой сборки или предварительной проверки не меняет работающий стек. При ошибке
самого обновления автоматического отката нет. При замене возможен краткий перерыв.
Старые образы не удаляются автоматически; следите за местом через docker system df.

Для отката выберите общий старый тег из docker image ls:

```bash
export IMAGE_TAG=<предыдущий-общий-тег>
docker compose up -d --no-build --wait --wait-timeout 90
```
