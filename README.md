# Cats: сборка и деплой на Raspberry Pi

Vue-сайт собирается Bun и раздаётся Nginx внутри Docker-контейнера.
GitHub Actions выполняет сборку и деплой на уже установленном self-hosted runner.
GitLab CI в этом репозитории не используется.

## Подготовка сервера

- Raspberry Pi с Linux ARM64 и настроенным GitHub Actions runner именно на сервере сайта.
- Runner должен иметь метки `self-hosted`, `linux`, `ARM64`. При нескольких подходящих
  runner добавьте уникальную метку сервера в `runs-on` в workflow.
- Docker Engine и Docker Compose plugin версии 2.20 или новее.
- Пользователь службы runner должен иметь доступ к Docker без интерактивного `sudo`.
  Проверьте `docker info` и `docker compose version` от его имени. После изменения
  членства в группе docker перезапустите службу runner. Доступ к Docker даёт
  широкие права на хосте: запускайте здесь только доверенный код.
- По умолчанию на сервере должен быть свободен TCP-порт 80. В GitHub:
  Settings → Secrets and variables → Actions → Variables можно задать
  `CATS_HTTP_PORT`, например `8080`, если 80 уже занят.

Секреты, SSH-ключи и registry для этого способа не нужны. Runner сам получает
задания по исходящему HTTPS; VPN можно оставить только для администрирования Pi.

## Автоматический деплой

Файл `.github/workflows/deploy.yml` запускается при push в `master`, если изменились
приложение, Compose или сам workflow. Также доступен Actions → Build and deploy cats
→ Run workflow; выбирайте ветку `master`. Другие ветки не деплоятся.

Одна джоба на одном runner последовательно:

1. Проверяет доступ к Docker и корректность Compose.
2. Собирает образ `cats:<commit>-<run-id>-<attempt>` под архитектуру самого Pi.
   Bun устанавливает зависимости по `bun.lock` с `--frozen-lockfile`.
3. Обновляет сервис `web` и ждёт успешного HTTP healthcheck внутри контейнера.
4. При ошибке выводит статус и последние логи.

Образы остаются локально на Pi. Старые образы автоматически не удаляются, чтобы
сохранить возможность отката; следите за свободным местом через `docker system df`.
Одновременно выполняется только один workflow деплоя для проекта.

При ошибке сборки работающий контейнер не меняется. При ошибке после его замены
джоба завершится с ошибкой; автоматического отката нет. На время пересоздания
контейнера возможен короткий перерыв. HTTPS и домен этим примером не настраиваются:
сайт доступен по HTTP на выбранном порту. Для публичного HTTPS нужен TLS-прокси
или отдельная настройка сертификатов Nginx.

## Запуск вручную

Из корня репозитория на сервере:

```bash
docker compose up -d --build --wait
docker compose ps
docker compose logs --tail 100 web
```

Откройте `http://<адрес-сервера>` (или добавьте выбранный нестандартный порт).
Для доступа из интернета настройте проброс TCP-порта на роутере и firewall.

Чтобы вручную выбрать порт:

```bash
CATS_HTTP_PORT=8080 docker compose up -d --build --wait
```

## Откат

Посмотрите сохранённые теги и выберите нужный:

```bash
docker image ls cats
export IMAGE_TAG=<предыдущий-тег>
export CATS_HTTP_PORT=80
docker compose up -d --no-build --wait --wait-timeout 90 web
```

Используйте тот же порт, что настроен для workflow.
